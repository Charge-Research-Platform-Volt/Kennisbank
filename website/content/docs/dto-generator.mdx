## Introduction
The `DtoGenerator` is a utility class that provides functionality to convert database entities into Data Transfer Objects (DTOs). It allows for selectively including nested relations using a simple, dot-notation syntax. The generator handles complex object graphs, collections, and maintains proper JSON serialization annotations.

## Converting Entities to DTOs
To convert an entity to a DTO, you can use the `ToDto` method:

```csharp
// Convert a resource to a DTO with no included relations
object resourceDto = DtoGenerator.ToDto(resource);

// Convert an entity and include specific properties
object resourceDtoWithType = DtoGenerator.ToDto(resource, "Type");
```

The `ToDto` method returns a dynamic object containing the properties of the entity. Properties with `[JsonIgnore]` attributes are excluded from the DTO unless explicitly included in the `includeProperties` parameter.

## Including Related Entities
One of the key features of the DTO Generator is the ability to include related entities using a dot notation syntax:

```csharp
// Include multiple relations
object resourceDto = DtoGenerator.ToDto(resource, 
    "Authors", 
    "Type", 
    "Tags"
);

// Include nested relations using dot notation
object resourceDtoWithNested = DtoGenerator.ToDto(resource, 
    "Authors.Person",
    "Authors.Person.Organisations",
    "Regions"
);
```

The dot notation allows you to specify how deep you want to include related entities. In the example above, the resource will include its authors, and for each author, it will include the related person entity with their organisations.

## How It Works
The DTO Generator works by recursively analyzing the entity's properties and converting them to a dictionary-based representation:

1. Primitive types (like strings, integers, dates, guids) are directly added to the DTO
2. Properties with `[JsonIgnore]` attributes are skipped unless explicitly included
3. Related entities (navigation properties) are recursively converted if specified in the include paths
4. Collections of entities are properly handled by converting each item in the collection

This approach provides a flexible way to control exactly what data is included in your API responses, helping to:

- Reduce payload size by only including needed data
- Prevent circular references in object graphs
- Customize the JSON structure for different API endpoints

## Examples

### Basic Usage
```csharp
// Get a resource from the database
Resource resource = await resourceManager.GetResourceAsync(resourceId);

// Convert it to a DTO
object resourceDto = DtoGenerator.ToDto(resource);

// Return as JSON result
return Ok(resourceDto);
```

### Including Relations
```csharp
// Get a resource with included relations
Resource resource = await resourceManager.GetResourceAsync(
    resourceId, 
    "Authors",
    "Type",
    "Tags"
);

// Convert to DTO with the same relations
object resourceDto = DtoGenerator.ToDto(resource, 
    "Authors", 
    "Type", 
    "Tags"
);

// Return as JSON result
return Ok(resourceDto);
```

### Including Nested Relations
```csharp
// Get an organization with included relations
Organisation org = await resourceManager.GetOrganisationAsync(
    organisationId, 
    "Persons",
    "OrganisationRelations"
);

// Convert to DTO with nested relations
object orgDto = DtoGenerator.ToDto(org, 
    "Persons.PersonRelations",
    "OrganisationRelations.TargetOrganisation"
);

// Return as JSON result
return Ok(orgDto);
```

<Callout title="Note">The DTO Generator intelligently handles circular references by only including the properties and relations that are explicitly requested. This prevents infinite recursion when converting complex object graphs with bidirectional relationships.</Callout>

<Callout title="Important">When using the DTO Generator with Entity Framework Core, make sure to include the necessary relations in your query using the `Include` method before converting to a DTO. Otherwise, the relations will be null when the DTO Generator tries to process them.</Callout>
